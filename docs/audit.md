# 原始 Lean 草稿审查记录

审查日期：2026-11-19。本文审查用户提供的原始代码片段，不代表项目当前文件的编译结果。当前验证结果应以实际构建日志与测试记录为准。

## 已确认的问题

1. **题目发生了变化。** 初始截图提到 PFR 猜想，而后续代码标题是弱哥德巴赫猜想。两者是不同的数学任务；本项目以用户后来提供的弱哥德巴赫代码为工作对象，不能作为 PFR 项目的交付证据。
2. **原稿只有两个引理。** 原截图要求三个引理或 SIMD 核心代码，原稿的两个 `sorry` 声明不能直接满足这些要求。
3. **主弧和次弧没有定义。** 原稿没有给出 `MajorArc`、`MinorArc`，也没有说明它们的参数、所在空间、分母范围或弧宽。需要显式定义这些对象，才能讨论声明的准确含义。
4. **主弧声明没有表达实际估计。** 其中的 `S` 是不受约束的存在量。取 `S = exp_sum N α`、`eps = 1`，左侧就是零，右侧非负。因此，即使证明了该声明，也没有证明奇异级数展开或 Hardy–Littlewood 主项估计。需要先定义具体主项，并给出有意义的误差项及统一常数。
5. **次弧声明不是 Mathlib 的 Big-O 表达方式。** Mathlib 使用函数之间、沿指定过滤器的 `f =O[l] g`。原稿把固定 `N` 的标量写成 `= O(...)`，既没有相应有效记号，也没有说明常数对 `α` 是否一致。对于本项目，明确写出 `∃ C > 0, ∃ N₀, ∀ N ≥ N₀, ∀ α ∈ minorArc ..., ...` 更便于审查。[Mathlib 官方渐近关系文档](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Analysis/Asymptotics/Defs.html)
6. **PR 依赖说明错误。** 原稿提到的 Mathlib4 PR #2345 实际是 `Data.Dfinsupp.Multiset` 的移植，不是圆法或素数指数和估计。[原始 PR](https://github.com/leanprover-community/mathlib4/pull/2345)
7. **版本说明不足以复现。** 只写 Lean 4.5.0 和 Mathlib4 不够；还需固定 Mathlib 的版本或提交，并提供 Lake 项目配置。Lean 4.5.0 中同名 `SpecialFunctions.Exponential` 文件主要处理 Banach 代数中的指数映射，不能仅凭文件名假定所有三角函数、对数及所需记号都已导入。[Mathlib v4.5.0 原文件](https://github.com/leanprover-community/mathlib4/blob/v4.5.0/Mathlib/Analysis/SpecialFunctions/Exponential.lean)
8. **`sorry` 不等于已证明。** 一个声明即使通过 elaboration，只要其证明仍含 `sorry`，也不能作为完成的形式化证明。原稿甚至尚未附带编译结果，不能据此声称框架已经通过 Lean 检查。
9. **没有 SIMD 实现或性能证据。** “private (NDA)” 和“可提供 benchmark”是原稿中的说法；原稿没有提供仓库、基准环境或结果，不能据此确认代码或 NDA 的存在。新的公开实现及实测记录应独立描述。

## 可诚实交付的基础层

可以先实现并验证素数指数和的定义、基础估计、明确的主次弧划分，以及有限区间验证结果的检查机制。这些可以成为后续分析证明的基础，但不能称为已完成圆法关键估计。

一个合适的阶段性验收包括：

- 实际证明指数和的模不超过求和中的素数个数；这是三角不等式给出的基础上界，不是次弧消去估计。
- 用显式集合定义主次弧并证明其覆盖和互斥；这是域划分的正确性，不是主弧渐近展开。
- 对明确的有限范围输出素数三元组证书，并检查每个证书的素性与和；有限区间的结果不能直接推广到所有奇数。

如果提供“有限范围 + 尾部定理 ⇒ 全局定理”的 Lean 拼接引理，必须保留尾部定理为显式假设。拼接引理的证明不会自动证明尾部假设。

## 仍需独立完成的分析部分

完整圆法路线至少还需要具体主项或奇异级数、带显式条件和常数的主弧误差估计、对整个次弧集合一致的估计、将积分与素数表示数连接的定理，以及覆盖所有相关奇数的阈值论证。它们不能通过重新命名基础引理、使用未验证引用或隐藏 `sorry` 来替代。
